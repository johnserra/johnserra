# Chat observability runbook

`POST /api/chat` emits one structured Vercel runtime-log object for every request. The event name is `chat_request_completed`; it is emitted after a streaming response terminates, including provider errors, timeouts, output-limit termination, and client cancellation. The implementation is provider-independent at the chat-core boundary and does not persist telemetry in Supabase or any other application store.

## Correlation and event schema

Every request generates a server-side UUID v4 before validation. A client-supplied value is ignored. The same value is returned in `X-Chat-Correlation-Id` on JSON errors and the NDJSON streaming response. Only this UUID is included in telemetry.

The exact JSON object keys are:

```json
{
  "event": "chat_request_completed",
  "schemaVersion": 1,
  "timestamp": "2026-09-12T12:34:56.789Z",
  "correlationId": "00000000-0000-4000-8000-000000000000",
  "route": "/api/chat",
  "locale": "en",
  "httpStatus": 200,
  "outcome": "success",
  "failureCategory": null,
  "durationMs": 842,
  "stages": { "validationMs": 1, "rateLimitingMs": 8, "preparationMs": 270, "generationMs": 563 },
  "diagnostics": {
    "totalDurationMs": 226,
    "rewrite": { "used": false, "reason": "standalone_single_turn", "fallback": false, "durationMs": 0 },
    "embedding": { "durationMs": 94, "fallback": false, "error": false, "reason": "success" },
    "retrieval": { "stage": "hybrid", "durationMs": 130, "candidateCount": 12, "fallback": false, "error": false, "reason": "success" },
    "reranking": { "durationMs": 2, "inputCount": 12, "outputCount": 6, "coverageAdjusted": 2 }
  },
  "retrieval": { "resultCount": 4, "candidateCount": 12, "noContext": false },
  "generatedUtf8Bytes": 516,
  "citationCount": 2,
  "hasCitations": true,
  "usage": {
    "generation": { "promptTokens": 820, "cachedInputTokens": 0, "candidateTokens": 180, "thinkingTokens": 0, "toolPromptTokens": 0, "totalTokens": 1000 },
    "rewrite": null,
    "embeddingTokens": null
  },
  "cost": {
    "generation": { "currency": "USD", "estimateUsd": 0.000696, "pricingSource": "https://ai.google.dev/gemini-api/docs/pricing", "pricingVerifiedOn": "2026-09-12", "pricingVersion": "gemini-2.5-flash-standard-text-2026-09-12", "model": "gemini-2.5-flash", "completeness": "complete" },
    "rewrite": null,
    "totalUsd": 0.000696
  },
  "toolCallCount": 0,
  "stopReason": "stop",
  "agentStopReason": null,
  "model": "gemini-2.5-flash"

```

The example uses a synthetic UUID, counts, and timings; it contains no visitor or source data. Unreached stage durations and unavailable metrics are `null`, not zero. A zero is used only for a reached numeric aggregate whose true value is zero, such as an empty generated byte count or the current non-agentic tool count.

`outcome` is `success`, `failure`, or `cancelled`. `failureCategory` is a stable enum (`invalid_request`, `rate_limited`, `preparation_timeout`, `retrieval_failure`, `provider_error`, `empty_output`, `output_limit`, and related boundary/service categories), or `null` only for success. `stopReason` is a normalized provider finish reason (`stop`, `length`, `safety`, `recitation`, `tool_error`, `unspecified`, `other`, or `unknown`); it is `null` when no provider finish metadata was received. `agentStopReason` is currently always `null` because this path has no agent loop.

## Metrics and investigation

Filter Vercel function/runtime logs for `event = chat_request_completed`, or use the equivalent JSON query in the Vercel dashboard/log export. The exact CLI flags vary by Vercel CLI version, so prefer the deployment’s Runtime Logs JSON view and filter on the event key rather than copying raw request logs.

Definitions use completion events as the denominator:

- Request count: count all completion events.
- Failure rate: events with `outcome = failure` divided by all events. Track `cancelled` separately; if an availability SLO treats disconnects as unsuccessful work, report `(failure + cancelled) / all` explicitly.
- No-context rate: reached events with `retrieval.noContext = true` divided by reached events where `retrieval.noContext` is non-null.
- Citation rate: reached generated events with `hasCitations = true` divided by generated events where `hasCitations` is non-null. `citationCount` is the number of Markdown HTTP(S) links in the transient bounded answer; text is never logged.
- Latency percentiles: p50/p95/p99 of `durationMs`, optionally split by `outcome`, locale, or failure category. Stage percentiles use the corresponding non-null stage field.
- Token totals: sum each non-null field in `usage.generation` or `usage.rewrite`; streaming snapshots are already cumulative/latest values and must not be summed per chunk.
- Cost totals: sum non-null `cost.generation.estimateUsd` and `cost.rewrite.estimateUsd`. Keep `completeness` visible and report partial estimates separately from complete estimates.

For an incident, follow this sequence:

1. Start with the `X-Chat-Correlation-Id` from the client response and locate its single completion event.
2. Check `outcome`, `httpStatus`, and `failureCategory`.
3. Compare the non-null stage durations to find the slow stage.
4. Check retrieval `resultCount`, `candidateCount`, `noContext`, and the sanitized retrieval diagnostics.
5. Check provider usage, stop reason, and complete/partial cost metadata.

The embedding SDK response currently exposes no general Gemini API token-usage field. Embedding work is represented by its stage diagnostics, while embedding tokens and cost remain unavailable (`null`); they are never guessed. Gemini 2.5 Flash Standard text estimates use the centralized rates verified on 2026-09-12 from [Google’s Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing): USD $0.30 per 1M uncached input tokens, $0.03 per 1M cached input tokens, and $2.50 per 1M output tokens including thinking tokens. Tool-use prompt tokens are treated as input. Cached tokens are removed from uncached input, and thinking tokens are counted once in output. Unknown models or absent usage produce no estimate; partial usage produces a marked partial estimate rather than a fabricated zero.

The current chat path has no configured model tools and does not execute model-selected function calls. It reports `toolCallCount: 0` and `agentStopReason: null`. Future agentic code must increment the count only after an application tool actually executes; a model-selected call alone is not execution.

## Privacy and retention

The telemetry API accepts only an allowlisted event shape and serializes one JSON object per line. It records no message text, query or rewrite text, generated answer, retrieved content, source titles/URLs/internal IDs, request body, IP address, session ID or hash, headers, provider/database error text, stack trace, credentials, API keys, or arbitrary error object. Citation metrics are computed from the transient bounded answer and then the answer is discarded. No telemetry table, cookie, fingerprint, or external telemetry service is used.

Vercel platform log retention is governed/configured in Vercel and is separate from application conversation storage. Operators must not add raw payload logging without revisiting the retention and disclosure policy in [persona and privacy guardrails](persona-privacy-guardrails.md). Runtime logs are operational evidence, not a conversation archive.
